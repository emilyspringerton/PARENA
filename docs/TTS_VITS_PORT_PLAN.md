# PARENA-native TTS: VITS (Piper fr_FR) port plan -- the model and the numeric oracle

Founder real-time, 2026-10-01: "dive into the TTS stuff with parena some kind of edge tts model", then the standing rule "always implement core deps in PARENA first". Output of the 2026-10-01 TTS feasibility investigation (workflow wf_853cfa47-f7d, investigator T-A; T-B numerics benchmark, T-C French G2P and T-E golden oracle were lost to a usage limit and still need running). Facts below were produced by running the commands, not inferred, unless a bullet says "inference".

## Summary

Both voices are the same single-speaker Piper-VITS "medium" architecture, 15.65M float32 params (62.6 MB), with no Loop/If/Scan subgraphs. Of 6183 (tom) / 2755 (siwis) ONNX nodes, only about 1000 do float math; the rest is exporter shape plumbing that disappears at batch=1. I rebuilt the whole inference path as a ~250-line pure-numpy reference (scratch/ta/vits_np.py) driven only by weights. It matches onnxruntime to rel-RMS 2e-6..4e-5 for BOTH voices at 12 settings (L=5..353, all three scales, injected noise), so one PARENA engine parameterised by weights serves both. Correction to the brief: siwis is 22,050 Hz, not 44.1 kHz; only tom is 44.1 kHz. Compute is 5.27 GMAC (10.5 GFLOP) per audio-second for tom and 2.80 GMAC for siwis; the decoder is ~80% of runtime. noise_scale=0 plus noise_w=0 gives bit-identical output across runs (same ORT config), and spectral/envelope proxies say it is acceptable, but tom loses its HF noise floor. A seeded PRNG at default scales is the better determinism mechanism. The biggest PARENA risk is the numeric substrate (F64-only, Vec-based NDArray, no conv), not the model.

## Risks

- PARENA numeric substrate (inference from reading source): F64-only scalars + Vec-based NDArray + per-element accessors almost certainly cannot reach the needed ~10 GFLOP per audio second (tom) at usable speed; I would expect 0.1-0.5 GFLOP/s from Vec-indexed loops, i.e. minutes per second of audio, versus ORT's ~45 GFLOP/s. Weights as F64 would also be 125 MB per voice. Fixing this (F32 type, raw typed buffers, vectorizable/restrict loops, blocked conv/GEMM kernels) is the real first task under the core-deps-are-PARENA-first rule, not the model port.
- Brief error: siwis is 22,050 Hz. Any downstream code (tyler_coldopen.c clip table, mixer, wav writer) must carry per-voice sample rate; mixing tom and siwis at one rate needs a resampler or per-clip rates.
- Bit-exact parity with ORT is impossible (ORT itself varies 1e-6..3e-5 with thread count/optimizer). durations come from ceil(exp(logw)*ls), which is discontinuous, so any tiny numeric difference can shift a phoneme by one frame (5.8 ms tom / 11.6 ms siwis) and then every later sample misaligns. Waveform-level tests must inject/pin durations (and noise) from the oracle; only the duration stage itself should be compared with a tolerance.
- Reproducibility of the PARENA engine itself across machines (inference): libm exp/tanh/erf and compiler FMA/vectorization choices change low bits; for CONSTRUCT-style reproducibility use PARENA-native exp/tanh/erf, fixed summation order, no fast-math, and a fixed PRNG algorithm. The spline inverse takes sqrt of a discriminant and divides by (-b - sqrt) with no guard in the graph (ORT would also NaN); I ran it in float64 in numpy without issue, keep float64 or guard in C.
- noise=0 is deterministic but not equivalent to default quality for tom: lower HF noise floor, more periodic (voiced fraction 0.62 vs 0.38-0.46), 3-5 dB lower mean per-bin level. Acceptable by proxies but unverified by ear. Also noise_scale=0 alone does NOT make output deterministic (noise_w must be 0 too), and noise_w=0 changes length (0.94x tom / 0.97x siwis) and removes prosodic variation.
- ONNX contains no length cap: w=exp(logw)*ls then ceil, T=sum can be huge for extreme noise_w or length_scale; the engine needs an allocation guard. Decoder activation memory is large for long clips (tom 10 s = 441k samples x 32 ch x 4 B = 56 MB per live tensor at the last stage, several live at once) unless decoded in chunks with the measured halos.
- Speaking rate is stochastic and voice dependent (tom 20.3 ids/s vs siwis 33.0 on the same sentence in one sample), so per-second cost figures for enc_p/dp vary with the sample; the flow/dec per-frame figures are exact.

## Recommendations / design

- Do not interpret ONNX. Port VITS directly: the model reduces to ~20 kernels (below). Use ta/vits_np.py (pure numpy, intermediates exposed through the dbg dict: x, m_p, logs_p, logw, wc, T, zp, z) plus the noise-injected ORT model from ta/validate.py make_injectable() as the conformance oracle, stage by stage, with rel-RMS <= 5e-5 for float stages and EXACT equality for the integer duration vector when fed oracle logw.
- Order of work under the PARENA-first rule: (1) add F32 (or raw f32 buffer) support and a vectorizable inner-loop story to PARENA; (2) kernels, hottest first: dilated Conv k3/5/7 at 128/64/32 channels and ConvTranspose (decoder = ~80% of time, Conv+ConvTranspose ~87% of ORT time), 1x1 conv as GEMM, depthwise k3 dilated conv (dp); (3) flow WN (k5 dil 1) and couplings; (4) encoder attention with the 9-wide relative window; (5) dp reverse spline; (6) length regulator + PRNG; (7) WAV + peak-normalize + int16 (matching Piper: per sentence chunk audio/max|audio|*32767 truncating). Decode with 12-frame halo and flow with 32-frame halo only if streaming is needed; offline pre-render does not need it.
- Weights: one-time converter ONNX -> flat keyed fp32 file (names from node scopes like enc_p.encoder.attn_layers.0.conv_q.w, since conv weights are 'onnx::' anonymous initializers in the ONNX; ta/vits_np.py load_weights() already does this mapping). Label the Python converter a STOPGAP with a PARENA protobuf-reader replacement item in EMILY/BACKLOG.md. Do not bother LZ4-compressing weights (zlib 1.08x). Ship per-voice: weights, phoneme_id_map (157 vs 154), sample rate (44100 vs 22050); defaults scales are identical (0.667,1,0.8).
- Determinism: implement a seeded PRNG in PARENA (xoshiro/PCG + Box-Muller or ziggurat) and keep the default scales for fidelity; expose seed. Provide a preset (0,1,0) as the bit-reproducible test mode and noise_w=0 when predictable duration/hold-fit matters. Draw order must be fixed (dp noise [2,L] first, then z noise [192,T] frame-major or channel-major, documented) so renders are reproducible.
- Use the exact erf GELU in the dp (tanh approximation gives only ~2e-3 logw error but can flip a ceil), reuse nothing from nn.prn's whole-array layernorm: LayerNorm here is over the 192 channels independently at each time step, biased variance, eps=1e-5, gamma/beta [192]. All 36 LayerNorms use that identical form.
- Exploit batch=1 simplifications: drop all masks and Constant/Shape/Unsqueeze/Reshape/Expand/ConstantOfShape/Cast plumbing; constant-fold exp(-logs)=1 in the 4 coupling layers (mean_only, ONNX computes Exp(Neg(zeros))); length regulator MatMul with the 0/1 path matrix = gather of m_p/logs_p columns by frame->phoneme index (searchsorted(cum, t, 'right')); spline masks/GatherND/ScatterND = one loop with `if |x|>5 passthrough`.
- Fit-to-hold for the TYLER cold open: 4 of 8 current clips overrun; use length_scale<1 (or noise_w=0 for predictability) rather than post-hoc clipping, and consider rendering offline at build time (214 GFLOP total, minutes even at 1 GFLOP/s) instead of at runtime until the engine is fast.
- Report/track tom (44.1k) separately from siwis (22.05k) in capacity planning: tom costs 1.9x per audio second (5.27 vs 2.80 GMAC) because the latent frame rate is 2x.
